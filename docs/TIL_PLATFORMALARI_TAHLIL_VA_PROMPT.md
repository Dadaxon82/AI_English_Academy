## 2-qism. Joriy etish uchun prompt (AI agent / dasturchi uchun)

Quyidagi blokni to'liq nusxalab AI kod agentiga (masalan, Claude Code) bering.

```text
ROL: Sen AI English Academy loyihasining katta full-stack muhandisisan.
Repo: github.com/Dadaxon82/AI_English_Academy  (sayt: https://dadaxon82.github.io/AI_English_Academy)
Stek: React 19 + TypeScript + Vite + Tailwind CSS 4 + PWA + Supabase (RLS);
mobil: mobile/ (Kotlin + XML Views). Interfeys to'liq O'ZBEK tilida.

MAQSAD: Memrise, Busuu, Babbel, Ling, Drops va Rosetta Stone platformalarining
isbotlangan yutuqlarini loyihaga MOSLASHTIRIB joriy etish. Nusxa ko'chirish EMAS:
ularning nomi, logotipi, rasmi, matni, ovozi ishlatilmaydi — faqat g'oya va mexanika.

ISHNI BOSHLASHDAN OLDIN:
1. README.md (ayniqsa 5d–5i bo'limlari), docs/LOYIHA_AUDIT_VA_AI_PROMPT.md,
   docs/TIL_PLATFORMALARI_TAHLIL_VA_PROMPT.md ni o'qi.
2. Mavjud modullarni qayta ishlat, dublikat yaratma:
   src/lib/srs.ts (SM-2), src/lib/mistakes.ts, src/lib/game.ts + gameConfig.ts,
   src/lib/planning.ts, src/lib/analyze.ts + ai.ts, src/content/canDo.ts,
   src/content/vocabEmoji.ts, src/components/ExerciseRunner.tsx, Mascot.tsx.
3. Har bir bosqich alohida PR bo'lsin; bosqich tugagach `npm run lint`,
   `npx tsc -b`, `npx vitest run`, `npm run build`, kerak bo'lsa Playwright e2e
   ishlat va natijani PR tavsifiga yoz.

O'ZGARMAS QOIDALAR (loyiha qoidalari — buzilmasin):
- Hech bir tugma dekoratsiya emas: har tugma haqiqiy harakat bajaradi.
- Soxta AI yo'q: AI ulanmagan bo'lsa qoidaviy dvigatel ishlaydi va UI'da
  `engine: 'rule-based'` ochiq ko'rsatiladi. AI kalitlari faqat serverda
  (Supabase Edge Function), kunlik limit AI_DAILY_LIMIT, 0005_ai_usage.sql dan foydalan.
- Soxta audio/video yo'q: fayl manifestda bo'lmasa pleyer umuman ko'rinmaydi.
  Ona tili egasi yozuvlari faqat HAQIQIY, litsenziyasi aniq fayllar bo'lsa qo'shiladi.
- Daraja faqat ko'p ko'nikma dalili bilan ko'tariladi (XP yoki kun bilan emas).
- Mikrofon audiosi rozilik siz serverga yuborilmaydi (`audio_stored: false`).
- Barcha sonlar gameConfig.ts ↔ game_manifest.json ↔ GameConfig.kt da bir xil;
  game-config.test.ts va GameManifestTest.kt yashil bo'lishi shart.
- Offline/PWA ishlashi buzilmasin; yangi ma'lumotlar sync navbatidan o'tsin.
- Yangi jadval = yangi migratsiya (0006_..., 0007_...) + RLS + index; eski sxemada
  ham ilova yiqilmasin (3b-bo'limdagi «rad etilgan ustunni tushirish» uslubi).
- WCAG 2.1 AA: kontrast ≥ 4.5:1, klaviatura, aria; axe testlari yashil.
- Veb va mobil xulqi bir xil (parity); mobil keyingi PR'da bo'lsa, README'da ochiq yoz.

BOSQICHLAR (ustuvorlik tartibida):

1-BOSQICH — Drops g'oyasi: «5 daqiqalik tezkor sessiya» va vizual lug'at
- Dashboard'ga «5 daqiqa» tugmasi: SRS'dan muddati kelgan so'zlar + 1 ta yangi
  mavzu; taymer src/lib/timer.ts orqali, IndexedDB'da saqlansin.
- Lug'at kartalarida vocabEmoji.ts dagi belgi/rasm; swipe (chap = «yana»,
  o'ng = «bilaman») — klaviatura muqobili bilan (← →).
- Kunlik reja (planning.ts) 90 daqiqa bo'lib qoladi; 5 daqiqa rejimi qo'shimcha
  «minimal kun» sifatida streakni saqlaydi (qoida gameConfig'da, testli).
- Testlar: sessiya tarkibi, taymer tiklanishi, streak qoidasi.

2-BOSQICH — Babbel g'oyasi: real hayot stsenariy-dialoglari + xatolar takrori
- Yangi kontent turi `dialogue` (src/content/types.ts): rollar, replikalar,
  bo'sh joylar, o'zbekcha qisqa grammatika izohi ("Nega shunday?").
- A1/A2 uchun har kunga 1 ta stsenariy (kafe, do'kon, yo'l so'rash, ish
  suhbati...). Kontent audit testi (content-audit.test.ts) yangi turni ham tekshirsin.
- Error Log'dagi xatolar avtomatik «Takrorlash menejeri»ga tushsin:
  mistakes.ts + srs.ts birlashgan navbat, bir xato ikki marta sanalmasin.

3-BOSQICH — Busuu g'oyasi: CEFR yo'li, inson tekshiruvi, sertifikat
- Progress sahifasida canDo.ts asosida «Men qila olaman» ro'yxati: har band
  qaysi dalil (mashq/mock natijasi) bilan tasdiqlangani ko'rinsin.
- «Tekshiruvga yuborish»: Writing/Speaking javobini boshqa o'quvchi yoki
  o'qituvchi tekshiradi. Jadvallar: peer_submissions, peer_reviews (RLS:
  muallif o'z yozuvini, tekshiruvchi faqat tayinlanganini ko'radi), shikoyat
  (report) tugmasi va moderatsiya holati. Rozilik siz audio yuborilmaydi.
  Tekshiruvchiga gem mukofoti (gameConfig'da son, testli).
- Daraja yakunida PDF/PNG «Yakunlash guvohnomasi» — lekin «rasmiy sertifikat
  emas, mashq natijasi» deb aniq yozilsin (mock imtihon qoidasiga mos).

4-BOSQICH — Memrise + Ling g'oyasi: AI rol-o'yin suhbati
- Speaking sahifasida «Suhbatdosh» rejimi: stsenariy tanlanadi (2-bosqich
  dialoglari), o'quvchi yozadi yoki gapiradi (Web Speech API, mavjud bo'lsa),
  javob Edge Function orqali AI'dan keladi; AI yo'q bo'lsa — oldindan
  yozilgan tarmoqlangan (branching) dialog daraxti ishlaydi va bu ochiq aytiladi.
- Har suhbatdan keyin: yangi so'zlar SRS'ga, grammatika xatolari Error Log'ga.
- «Real nutq» klipi: faqat litsenziyali haqiqiy audio/video bo'lsa ko'rsatiladi
  (manifest orqali), aks holda bo'lim yashirin.

5-BOSQICH — Rosetta Stone g'oyasi: talaffuz bali va immersion rejimi
- Talaffuz mashqi: maqsad jumla → yozib olish → nutqni tanish natijasini
  maqsad matn bilan so'zma-so'z solishtirish (Levenshtein), noto'g'ri so'zlar
  qizil bilan. Ball «taxminiy» deb belgilanadi; brauzer qo'llamasa sabab
  ko'rsatiladi, soxta ball berilmaydi.
- Sozlamalarda «Immersion rejimi» (B1+ uchun tavsiya): mashqlarda o'zbekcha
  tarjima yashiriladi, rasm/kontekst orqali tushuntiriladi; istalgan payt
  «Tarjimani ko'rsatish» tugmasi.

6-BOSQICH — motivatsiya va o'lchov
- Har yangi funksiya uchun hodisa (event) yozuvi: ishlatilish soni, tugatish
  foizi — faqat foydalanuvchi qurilmasida va RLS bilan himoyalangan jadvalda.
- README «Joriy sonlar» bloki `npm run stats` bilan yangilansin (qo'lda emas).

QABUL MEZONLARI (har bosqich uchun):
- [ ] Funksiya veb'da ishlaydi, light/dark va 375px telefon ekranida tekshirildi
- [ ] Loading / empty / success / error holatlari bor
- [ ] Unit testlar + kamida 1 ta e2e ssenariy; axe — 0 buzilish
- [ ] ESLint 0 ogohlantirish, tsc 0 xato, build muvaffaqiyatli
- [ ] Offline holatda ham ishlaydi yoki nega ishlamasligi ochiq aytiladi
- [ ] README'ga yangi bo'lim: nima qilindi, qaysi fayllar, qaysi sonlar manbasi
- [ ] Mobil parity holati yozildi (qilindi / keyingi PR)

NATIJA FORMATI: har bosqich oxirida qisqa hisobot — o'zgargan fayllar,
yangi migratsiyalar, test natijalari (raqamlar bilan), ma'lum cheklovlar.
Taxmin qilingan son yozma; faqat o'lchangan natija.
```
